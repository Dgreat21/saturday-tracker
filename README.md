# Saturday Tracker

> Local AI-powered task tracker for a single person, based on the local
> file system, with a pretty UI.

Таск-трекер, у которого источник истины — **обычные CSV-файлы рядом с вашим кодом**,
а не база данных и не облако. Тикеты лежат в git вместе с проектом: их видно в diff,
их можно грепнуть, смержить и откатить, а история правок — это история коммитов.

Изначально сделан для совместной работы человека и AI-агентов над одним проектом:
агент читает `tasks.csv` одной командой без API, пишет через тот же мьютекс, что и UI,
и не может «случайно» разойтись с тем, что видит человек в браузере.

```
tracker/
├── tasks.csv        # задачи: epic / story / task / bug
├── goals.csv        # цели, проекты, вехи
├── links.csv        # связи между тикетами (ребро пишется один раз)
├── sprints.csv      # спринты
└── comments/        # обсуждение: по markdown-файлу на тикет
```

## Быстрый старт

Нужен только Python 3.11+. Зависимостей нет.

```bash
git clone https://github.com/Dgreat21/saturday-tracker.git
cd saturday-tracker
python3 -m saturday_tracker            # http://127.0.0.1:8777 на демо-данных
```

Свой каталог с данными:

```bash
python3 -m saturday_tracker --data ~/projects/myapp/tracker
# или
export SATURDAY_TRACKER_DATA=~/projects/myapp/tracker
```

Пустой трекер заводится копированием примера:

```bash
cp -r examples/tracker ~/projects/myapp/tracker
```

## Что умеет

- **Доска и список** с фильтрами, карточка тикета, спринты, цели с прогрессом.
- **Прямые ссылки на тикет** — `http://127.0.0.1:8777/t/DEMO-2` открывает карточку
  сразу. Удобно давать ссылку вместо пересказа: пересказ устаревает, ссылка нет.
- **Граф связей и диаграммы** (mermaid): граф задач, канбан, поток. Рисуются
  из данных, а не хранятся картинками.
- **Запись из интерфейса**: статус, спринт, комментарий, связь, создание тикета.
  Каждая правка — атомарная запись файла и отдельный git-коммит.

## Почему файлы, а не база

Это осознанный выбор, а не отсутствие рук:

- **Diff и merge.** Изменение статуса видно в code review. Две ветки с правками
  тикетов сливаются git-ом, а не экспортом-импортом.
- **Агент читает без API.** `grep "^DEMO-" tasks.csv` — и весь контекст на месте.
  Бинарная база требует клиента и слоя доступа.
- **Нет отдельного бэкапа.** История правок = история репозитория.
- **Ничего не поднимать.** Ни сервера БД, ни миграций, ни docker-compose.

Границы применимости честные: это трекер для одного проекта и небольшой команды.
На десятках тысяч тикетов и многопользовательской конкурентной записи из разных
сетей правильный выбор — база; здесь этой задачи нет.

## Гарантии записи

Запись — самая опасная часть, поэтому она вынесена в отдельный модуль
(`tracker_store.py`) и обвешана проверками:

1. **Мьютекс** (`ctx_lock.py`) — межпроцессный лок на каталогах, атомарный `mkdir`.
   UI и агент, пишущие одновременно, не затирают друг друга.
2. **Атомарная подмена** — запись во временный файл и `os.replace`. Читатель видит
   либо старый файл целиком, либо новый, но никогда половину.
3. **fsync** до подмены: «записано» означает «на диске», а не «в page cache».
4. **Поле `обновлено`** проставляется само.
5. **git-коммит** на каждую правку — если каталог данных под git. Не под git —
   трекер работает без истории, это не ошибка.

Ошибка любого шага поднимается наверх и показывается человеку. «Сохранилось,
но нет» — худший исход, поэтому его нет.

## Проверки

```bash
python3 -m saturday_tracker.tracker_selftest
```

Селфтест проверяет и сам себя: у каждого класса проверок есть **негативный
контроль** — заведомо испорченные данные, на которых проверка обязана покраснеть.
Зелёный тест, который не умеет краснеть, ничего не доказывает.
