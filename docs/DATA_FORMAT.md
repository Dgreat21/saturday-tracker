# Формат данных

Все файлы — CSV в кодировке UTF-8 (допускается BOM: его пишут Excel и Numbers).
Разделитель — запятая, переводы строк сохраняются как в исходном файле
(CRLF не превращается в LF при записи).

## tasks.csv и goals.csv

Обе таблицы имеют одинаковый набор колонок — это позволяет показывать их
единым списком и связывать между собой.

| Колонка | Что это |
|---|---|
| `ключ` | `<НАПРАВЛЕНИЕ>-<номер>`, например `DEMO-1`. Уникален, не переиспользуется |
| `тип` | tasks: `epic` / `story` / `task` / `bug`; goals: `цель` / `проект` / `веха` |
| `название` | короткая строка |
| `автор` | кто завёл |
| `согласовано` | `да` / `нет` — подтверждена ли задача владельцем |
| `статус_тег` | из словаря ниже |
| `статус` | текущее положение своими словами |
| `описание` | контекст, достаточный чтобы взять задачу в работу |
| `dod` | Definition of Done, пункты через `;` |
| `резолюция_тег` | `решен` / `не решен` — заполняется при закрытии |
| `резолюция` | пост-мортем: что вышло, что поняли |
| `спринт` | ключ из `sprints.csv` или пусто |
| `создано` / `обновлено` | `YYYY-MM-DD HH:MM`, поле `обновлено` ставится автоматически |

### Словарь `статус_тег`

| Тег | Значение |
|---|---|
| `в беклоге` | не взята в работу или недостаточно описана |
| `анализ` | сбор контекста, выработка решения, оценка рисков |
| `планирование` | конкретные шаги до DoD, сверка достижимости |
| `разработка` | выполнение шагов |
| `тестирование` | проверка исполнителем |
| `ревью` | на просмотре у автора или заказчика |
| `закрыт` | завершена; `резолюция_тег` обязателен |

Значение вне словаря запись отвергает — это проверяется в селфтесте.

## links.csv

```csv
откуда,тип,куда
DEMO-2,входит в,DEMO-1
DEMO-3,блокирует,DEMO-1
```

**Ребро пишется один раз.** Обратная сторона выводится при чтении: если
`DEMO-3 блокирует DEMO-1`, то на карточке `DEMO-1` показывается
«блокируется DEMO-3». Хранить обе стороны означало бы иметь два источника
истины об одном факте.

Типы: `блокирует` · `входит в` · `реализует` · `дублирует` · `относится к`.
Связь тикета с самим собой отвергается.

## comments/&lt;КЛЮЧ&gt;.md

Обсуждение — обычный markdown, по файлу на тикет:

```markdown
# Комментарии: DEMO-2

## user · 2026-01-13 11:20

Текст комментария.
```

Формат выбран так, чтобы комментарий читался и правился без трекера —
в редакторе, в git-diff, грепом.

## Почему CSV, а не JSON

CSV даёт **построчный diff**: правка одного тикета — одна изменённая строка,
и её видно в code review. В JSON переформатирование сдвигает всё дерево,
а слияние двух веток превращается в ручную работу.

Плата за это — экранирование: многострочные описания лежат в кавычках,
внутренние кавычки удваиваются. Это стандарт RFC 4180, его понимают Excel,
pandas и `csv` из стандартной библиотеки.
