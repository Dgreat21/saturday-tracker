# Участие в разработке

## Запуск из исходников

```bash
git clone https://github.com/Dgreat21/saturday-tracker.git
cd saturday-tracker
python3 -m saturday_tracker          # демо-данные, http://127.0.0.1:8777
```

Зависимостей нет — только Python 3.11+ и стандартная библиотека. Это осознанное
ограничение: трекер должен запускаться там, где ставить пакеты нельзя или лень.

## Перед тем как отправлять правку

```bash
python3 -m saturday_tracker.tracker_selftest
```

Селфтест обязан быть зелёным. Если вы добавили проверку — **добавьте к ней
негативный контроль**: прогон на заведомо испорченных данных, где проверка
обязана покраснеть. Проверка, которая не умеет краснеть, не принимается:
она создаёт ложную уверенность, а это хуже её отсутствия.

## Что важно сохранять

- **Запись только через `tracker_store`.** UI и любой другой код не пишут в файлы
  напрямую — иначе гарантии (лок → атомарность → fsync → git) обходятся молча.
- **Формат данных читаем человеком.** Если правка делает CSV непригодным для
  чтения глазами и грепом, у неё должна быть очень веская причина.
- **Ошибки поднимаются наверх.** «Сохранилось, но нет» — худший исход; лучше
  показать пользователю ошибку, чем проглотить её.

## Стиль

- Комментарии и документация — по-русски, как и весь проект.
- Комментарий объясняет **почему**, а не пересказывает код.
- Имена полей в CSV — по-русски: файлы читают люди, а не только программы.

## Ограничение: фронтенд

`static/tracker_app.html` — собранный бандл, исходников которого в репозитории
нет. Правки во фронт вносятся патчами (`tracker_write_patch.py`) по строкам-маркерам.
Если вам нужно менять фронт существенно — заведите обсуждение: скорее всего,
правильным решением будет вынести исходники фронта в подпроект, а не наращивать
патчи. Подробности — `docs/ARCHITECTURE.md`.
